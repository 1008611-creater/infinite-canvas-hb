## ⚠️ 不要带错的前提

**`ai.cauai.fun` 的积分账本（`spend-grants`、commerce-console 那一套）不适用于本产品。**

那是念念 Studio 画布 / commerce 工作线的模型，另一套代码、另一套数据、另一个域名。把它的计费逻辑搬到这里，只会得到一份无法实施的方案。

## 现在的真实收益面

### 1. 站点密码门禁 —— 这决定了商业形态

门禁意味着**它不是公开产品**。任何"靠自然流量变现"的想法在当前形态下都不成立——陌生人根本进不来。

反过来说，门禁是**可控性资产**：用户名单是你手动给的。这是小规模付费交付的前提。

### 2. 免费视频模型 —— 这是真正的天花板

代理**只开放免费的 `agnes-video-2.5-flash`**，付费的 `agnes-video-2.5` 被代理拒绝、前端隐藏。

叠加免费额度的限流：**约 1 次/分钟**，超了返回 `429 rate_limit_exceeded`。

这意味着：

- 出片速度被卡死在每分钟一条
- 没有高质量付费模型的输出
- **不可能对外卖服务** —— 你卖不出你产不出的东西

**收益的第一优先级不是定价，是解锁付费模型。** 顺序错了，后面全是空谈。

### 3. 页面赞助 / 广告位

上游 README 自带 **3 个赞助位**，本 fork 保留了：

| 赞助方 | 说明 |
|---|---|
| Atlas Cloud | 赞助位 |
| 秘塔 MiniMax H3 | 明码标价：768P **0.09 元/秒**，2K **0.15 元/秒** |
| Infistar.ai | 赞助位 |

这三个位置是现成的**版位库存**，只是目前没有对外招商。如果站点开放给外部用户，这是最直接的变现形式，且不需要自己建计费系统。

### 4. `license-server` —— 独立产品，不算在这里

`dola.cauai.fun` 的豆包客户端卡密授权服务是**另一个产品**，跟画布没有关系。它目前也还是原型状态。

**不要把它折进画布的收益模型**，也不要因为"都是自己的项目"就把两条收入混着算。

## 收益路径（按现实性排序）

| 顺序 | 路径 | 前提 | 现状 |
|---|---|---|---|
| 1 | **解锁付费视频模型** | 代理侧放行 `agnes-video-2.5`，定义成本边界 | 未做 |
| 2 | **赞助位招商** | 站点对外可见 | 有 3 个空位，未招商 |
| 3 | **邀请制付费席位** | 门禁 + 手动发号 + 收款 | 无任何支撑设施 |
| 4 | **额度包 / 积分制** | 先有账号计费与用量统计 | 无 |
| 5 | **开源影响力 → 咨询服务** | fork 有差异化（三模式） | 未运营 |

### 关于 3 和 4

这两条都需要**先建计费基础设施**：账号体系（已有基础，`canvas-api` 存在）、用量统计（没有）、额度扣减（没有）、支付通道（没有）。

而且必须先解决一个前置问题：**改视频模型要重建代理，重建代理要动服务器密钥，动密钥有泄露风险。** 计费系统的设计要连着这条链路一起考虑，不能只画前端。

### 成本红线

**任何付费调用都必须逐次明确授权。** 调用前说清楚：几次、哪个模型、什么分辨率。

免费的 `agnes-video-2.5-flash` 在 720P 限时免费期间可以放开跑。

MJ 抽卡只用于人物/建筑/场景，且结果**先进候选目录，人工 4 选 1 才升为正式资产**——不要自动把抽卡结果转成正式素材，那会烧额度。
