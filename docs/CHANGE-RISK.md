# 变更风险分级 · 无限画布（hb.cauai.fun）

> **本文件解决「所有改动走同一套流程」的问题**（`CONSTRAINTS.md` C8.1）。
> 不是每个改动都值得开九阶段流程；也不是每个改动都能"自测一下就发"。
> 版本：v1.0 · 2026-09-17

---

## 1. 分级定义

| 级别 | 定义 | 本项目的典型例子 |
|---|---|---|
| **L0** | 文案、样式、纯文档、注释。**不改变任何行为。** | 改本仓文档措辞；补一份 STATUS 记录；调整 Markdown 排版 |
| **L1** | 单模块内部逻辑改动。**对外契约不变。** | 前端某个组件的交互修正；`canvas-api` 单条路由的内部实现；本地脚本改参数 |
| **L2** | 跨模块 / 对外接口 / 前端常量改动。**别人可能依赖它。** | 新增 API 路由；改 `channel-templates.ts`；改前端默认配置；改数据模型字段 |
| **L3** | 鉴权、资金、数据、部署、架构。**错了不可逆或直接影响钱。** | 落批次 1（额度/扣费）；改门禁或 `AUTH_COOKIE`；改 nginx 路由；动服务器数据卷；对外暴露 `canvas-agent`；任何发布动作 |

## 3. 快速判定（30 秒自检）

从上往下，命中第一条即为该级：

1. 会**花钱**、会**动用户数据**、会**改变谁能访问什么**、会**动服务器**吗？ → **L3**
2. 会改**对外接口**、**数据模型**、**前端默认配置**，或跨模块吗？ → **L2**
3. 会改变某个模块内部的**行为**（哪怕是修 bug）吗？ → **L1**
4. 只改文字/样式/文档/注释？ → **L0**

**判定不清时，往高靠一级。** 高估的代价是多花时间，低估的代价是线上事故。

## 4. 本项目的强制 L3 清单

以下动作**无论改动多小，一律 L3**，不许降级：

| # | 动作 | 理由 |
|---|---|---|
| 1 | 任何对权威源码树 `infinite-canvas\` 的写入 | 连着 `AUTH_COOKIE` 与三个不可再生数据卷 |
| 2 | 执行 `scripts/deploy/publish.sh` | 发布 = L3，无例外 |
| 3 | 改 `AUTH_COOKIE` / `PROXY_ACCESS_TOKEN` / 注册开关 | 一次改错 = 全体掉线或陌生人进得来 |
| 4 | 改 nginx 路由（含 `/ziyu/`、`/dav/`、`/agnes/`） | 门禁与资金敞口的物理边界 |
| 5 | 改或删 `/opt/` 下任何数据卷 | 不可再生 |
| 6 | 改 `.env` 并重建容器 | "改了还是旧的"且日志无痕，最难排查 |
| 7 | 对外暴露 `canvas-agent`（批次 3 A-19） | token 泄露 = 整机可被驱动 |
| 8 | 任何扣费/退款/发码逻辑 | 直接影响钱 |

## 5. 与批次的关系

**批次 ≠ 风险级。** 批次是"发布范围"，风险级是"流程轻重"。

| 批次 | 典型风险级 |
|---|---|
| 批次 1（紫域 + 额度/卡密） | **L3**（落权威树 + 钱） |
| 批次 2（撤门禁 + 公开注册 + 试拍） | **L3**（鉴权 + 发布） |
| 批次 3（agent 对外 + LLM 中转） | **L3**（对外暴露 + 架构） |

每个批次内部再按任务拆：比如批次 1 里"前端加一个余额显示"可以是 L2，
"改扣费逻辑"必须是 L3。**按任务定级，不按批次定级。**

## 6. 豁免

任何一条要求都可以申请豁免，但必须：

1. 写进 `docs/DECISIONS.md`（编号 E-xx）；
2. 注明：豁免哪条 / 为什么 / 有效期 / 谁批的；
3. **L3 的 G3 书面批准不可豁免。**
