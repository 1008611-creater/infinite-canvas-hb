## 静态基线（2026-09-21）

已对权威源码完成定位，并在 G3 批准后完成第一处最小改动：

- `web/src/pages/canvas/project.tsx` 已有 `connectedNodesByNodeId`、`handleGenerateNode` 和节点状态常量；这能支持单节点生成与引用关系，但目前没有被证据证明的独立“多节点链执行器”。
- `web/src/lib/canvas/canvas-chain.ts` 现在按确定性广度优先顺序递归解析上游节点，在资源节点处停止；`canvas-resource-references.ts` 只把资源边界节点交给生成逻辑，因此 `image → config → video` 不再被一跳查找静默截断，也不会把配置节点混入资源输入。
- `project.tsx` 对同一目标节点的活动生成请求做前置去重；视频无提示词且无参考输入时在提交前阻止并提示；每次主流程/重试的业务请求 ID 传入视频提交；`video.ts` 将其写入 `Idempotency-Key`，同时不再把下载失败的临时远程 URL 当作成功结果，无法写入本地媒体存储时会进入失败路径。
- `file-storage.ts` 的视频/音频元数据读取增加超时兜底，媒体事件异常时不会把生成节点永久留在 loading 状态。
- 视频节点现在持久化 `generationRequestId`、`generationTaskId` 与 `queued/running/completed/failed` 状态；刷新时由 `resetInterruptedGeneration` 将未完成任务恢复为明确失败，不留下永久 loading。
- `web/src/lib/canvas/canvas-chain.test.ts` 覆盖中间配置节点、汇聚分支去重和环路终止；相关专项原生 Node 测试合计 6/6 通过。
- `web/src/stores/channel-templates.ts` 已生成 `Idempotency-Key`，需要在 T2 中确认它与链执行的任务边界一致，而不是只覆盖单个渠道脚本。
- `canvas-api/routes-credits.js` 与 `canvas-api/ziyu.js` 已有结果持久化入口；T2/T3 必须证明真实调用发生，而不能只证明函数存在。

已完成的专项验证：原生 Node 契约测试 6/6 通过（链路解析 2 项、状态恢复 2 项、视频幂等请求头 2 项）；`web` 类型检查通过；生产构建通过。构建仅保留既有的动态导入和大 chunk 警告。

上述不是完整功能通过结论；结果落盘、状态恢复、重复提交和错误路径仍以 G4 的真实浏览器和服务端证据为准。
- `agnes-video-proxy/idempotency-store.js` 现把 `Idempotency-Key` 约束落到代理提交边界：相同 key + 相同请求摘要共享一个上游 Promise；摘要不同返回 409；失败后允许重试；CORS 预检同步放行该请求头。
