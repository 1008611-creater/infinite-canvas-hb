# Task Spec：hb.cauai.fun 画布升级到 v0.19

## 背景和目标

- [用户确认] 线上公开售卖的画布应更新到 v0.19；用户反馈网页没有变化。
- [已验证] 本地构建版本由仓库根目录 `VERSION` 注入前端；权威源码目前标记 `v0.16.0`。
- [已验证] 上游 `v0.19.0` 不只是版本号，包含真实功能变更。目标是把需要的上游 v0.17–v0.19 功能带入 HB 版本，同时不丢失 HB 定制能力。
- 目标：形成隔离、可构建、可审查的 v0.19 候选；此任务本身不发布线上。

## 本次范围

- 将上游 `v0.19.0` 的实际产品功能有选择地移植到 HB 版本，尤其核实该版本变更清单及用户可见的画布功能。
- 保留并回归验证 HB 的登录/认证、余额读取、额度预扣/结算/退款、紫域与 Agnes 渠道、视频生成、文件存储与同步等定制路径。
- 版本号与页面展示的版本信息统一为 `v0.19.0`，并由构建产物可读取地证明。
- 所有代码修改限于隔离候选；发布前不改权威源码工作区，不连接或写入线上数据库，不发起真实生成、扣费、退款或注册操作。
- 记录规格、自测、事后审查、两份独立审查及问题闭环证据。

## 本次不做

- 不以单独修改 `VERSION` 冒充完成上游升级。
- 不覆盖或重置已有候选、权威工作区、用户项目或数据卷。
- 不发布线上，不修改服务器配置、密钥、注册开关、额度数据或用户数据。
- 不以浏览器缓存清理作为代码升级的替代方案。

## 业务规则

- RULE-BIZ-001：公开售卖版本的真实代码能力、页面版本号和构建版本指纹必须一致。
- RULE-BIZ-002：上游功能移植不得破坏现有 HB 专有工作流。
- RULE-BIZ-003：任何真实生成/扣费/退款验证均须另行获得当次授权；本次优先用单元、契约与模拟数据验证。

## 权限规则

- RULE-AUTH-001：HB 登录态、API 鉴权与现有计费后端边界不得被上游前端改动绕开。
- RULE-AUTH-002：紫域/Agnes 请求不得通过前端直连绕过服务端额度校验、幂等与结算/退款。
- RULE-AUTH-003：新注册用户不得因“首个用户”或初始化路径自动获得管理员权限。

## 数据规则

- RULE-DATA-001：不访问或修改线上不可再生数据卷、账号、项目、余额、账本和兑换记录。
- RULE-DATA-002：版本升级不得更改现有画布/节点持久化结构而没有兼容读取或迁移依据。
- RULE-DATA-003：同步与媒体引用升级必须保持旧数据可读取，失败路径不得静默删除或覆盖用户数据。

## 影响范围

- 代码：前端画布、图像/视频生成 API、设置/存储/同步、Agent 与插件、版本信息、上游变更涉及的服务端路径。
- 风险：L3（版本升级触及鉴权、计费及部署边界）。
- 线上影响：候选阶段无；线上当前版本不变。

## 推荐实现步骤

1. 对照上游 v0.16–v0.19 变更记录，整理功能映射与 HB 定制保护清单。
2. 仅在隔离候选解决冲突；逐项记录采纳、改写或排除的原因，不能粗暴用单侧版本覆盖。
3. 执行依赖安装/锁文件检查、类型检查、单元/契约测试、生产构建和版本产物检查。
4. 完成逐文件、端到端执行链路的事后审查，并形成 worker-report。
5. 安排两名只读独立审查员：A 检查 v0.19 上游功能覆盖和兼容；B 检查 HB 鉴权、额度、扣费、紫域/Agnes 与数据兼容。
6. 关闭阻断问题后形成候选交付记录。线上发布仍须满足项目发布 D44 的独立会话确认与当次授权。

## 验收标准

- AC-001：候选源码 `VERSION`、页面/客户端可见版本和 `dist/BUILD_INFO.txt` 均显示 `v0.19.0`；构建产物指纹可区分线上旧版。
- AC-002：逐项对照上游 v0.19 发布记录，至少形成变更映射表；纳入的功能有对应代码或测试证据，未纳入项有明确理由。
- AC-003：旧的已保存画布与节点样例可加载、保存并重新加载；相关错误路径有自动化测试或等效可复核记录。
- AC-004：登录鉴权、余额/额度检查、预扣、成功结算、失败退款/释放、幂等重试及紫域/Agnes 后端代理路径的既有测试全通过；不存在前端绕过服务端计费的新路径。
- AC-005：注册首用户不自动成为 admin 的已有安全测试通过；不触及线上注册和账号数据。
- AC-006：文件存储、媒体引用、云同步路径的已有测试通过；无任何删除、重置或迁移线上数据动作。
- AC-007：生产构建、类型检查、关键单元/契约测试、`git diff --check` 通过；完整记录命令、结果和环境。
- AC-008：worker-report 完成，并经过一次逐文件及端到端事后审查；结论和未覆盖边界明确。
- AC-009：两名独立 reviewer 分别产出报告，逐项判定 AC；两份报告均无未关闭的 blocking 问题，审查期间不修改代码。
- AC-010：候选与线上明确区分；未取得发布 D44 所需新确认前，线上保持不变。

## 待确认事项

- [待核验] 此任务只准备候选和独立审查，不包含线上发布。既有“做完直接发布”授权仍受项目 D44 发布前新确认限制。
- [待核验] 浏览器右侧当前实际显示的线上版本尚未由本次工具读取；不得将本地候选版本误报为线上版本。
