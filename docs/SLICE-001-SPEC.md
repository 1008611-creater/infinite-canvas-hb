# 垂直切片 001 · 可执行规格

> 对应 Problem Brief：`docs/SLICE-001-PROBLEM-BRIEF.md`。
> 本规格只定义验收，不代表已经实现。

## 主流程

1. 测试账号登录并打开一个已有画布项目。
2. 读取一个已有图片素材节点和一个视频节点；若画布没有这两个节点，按验收脚本创建。
3. 从图片节点连接到视频节点，确认方向为 `image → video`，重复连接不得产生第二条边。
4. 在视频节点选择允许的测试模型和时长，提交一次执行。
5. 看到明确的 `queued/running` 状态；页面刷新后状态仍可恢复。
6. 成功时视频结果成为可引用媒体，画布节点不只保存一次性远程 URL。

## 错误流程

- 输入素材缺失：阻止提交并显示可行动提示。
- 模型或参数不合法：阻止提交，不产生上游调用。
- 上游超时/限流：任务进入 `failed`，显示错误类别，不能永久 loading。
- 用户重复点击提交：同一业务任务只产生一次上游提交，依赖 `Idempotency-Key` 或等价幂等机制。
- 结果 URL 已失效：显示“结果已过期/未取到”，不得写入假媒体记录。

## 验收标准

| 编号 | 标准 | 证据 |
|---|---|---|
| S1 | 项目、节点、连线在刷新后可恢复 | 浏览器截图 + 节点/连线读回记录 |
| S2 | 连线方向为图片到视频，重复连接不增加边 | DOM/状态断言落盘 |
| S3 | 提交只发生一次，带可追踪任务标识 | 浏览器网络记录或服务端日志 |
| S4 | `queued → running → completed` 或明确 `failed`，无永久 loading | 状态时间线 |
| S5 | 成功结果写入媒体记录，刷新后仍能播放/读取 | 媒体 API 响应 + 页面复核 |
| S6 | 失败路径不写假成功；扣费/结算状态可对账 | API 响应、数据库查询或对账记录 |
| S7 | 治理仓质量门仍为 0；源码专项验证全部通过 | `node scripts/verify.mjs` + 项目验证命令 |

## 数据与安全边界

- 浏览器只保存用户侧配置和画布引用，不保存服务器密钥。
- 上游密钥只由服务器环境注入；前端只能使用代理入口。
- 真实执行前必须确认测试账号、额度上限和回滚方式。
- 不可再生数据卷按 `AGENTS.md` §5 处理，禁止用测试清理代替回滚。

## 范围澄清（2026-09-21）

本垂直切片的已实现输入边界是“视频提示词或图片参考 → 视频”；视频/音频作为参考素材仍不在本切片的实现范围内。相关错误键和后续能力可以保留，但在接入前不得作为当前可用能力对用户承诺。S2 的“参考关系”因此特指图片到视频。
