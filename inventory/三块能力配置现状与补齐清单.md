## 二、逐块补齐方案（批次1收得到钱已完成，批次2放得开准备中，批次3跑得顺准备中）

### 1. 图片（你缺一个图片上游）
画布图片要求 **OpenAI 兼容 `images/generations`** 或 **Gemini `v1beta`**。你本机的图片渠道(MXAI/Dola/Midjourney)是 **RPA/网页脚本**、不是这个协议，接不进来。
- **推荐**：找任一 OpenAI 兼容生图 API（change2pro/krill 等中转一般有 `gpt-image-1` 类），拿 baseUrl+key：
  baseUrl=`https://...中转...`、key=你的 key、加一个 `capability:image` 的模型(如 `gpt-image-1`)。
- 然后把图片模型设成它（在 `/config`，或改预置脚本的 `imageModel`）。

### 2. LLM（对话/Agent 驱动）
画布与 Agent 都要求 **Codex/OpenAI 兼容 `chat/completions`**。
- 你 `~/.codex/config.toml` 已配多个中转（krill / deepseek / change2pro / omniroute），**证明你有可用 LLM key**。
- 在画布 `/config` 新增一个 channel 指向其中一个中转（如 `https://api.change2pro.com`+你的key），加一个文本模型(如 `gpt-4o`/`deepseek-chat`)，设默认。
- 画布侧 Agent 面板用的是 **Codex**(本地驱动)，不是画布的 LLM channel——见下。

### 3. MCP / 让"AI 用画布"（批次1收得到钱已完成，批次2放得开准备中，批次3跑得顺准备中）(你关心的核心)
画布 → Agent 的机制是：**本地 `canvas-agent`(TCP17371) + 本地 Codex as 大脑**，画布右栏连上后，你在画布对话框直接叫 AI 操作画布(建节点/连线/查询状态)。**这条路可跑，你机器具备全部前提**：
- `codex` bin：✅ 已有 (`~/AppData/Roaming/npm/codex`)
- Codex 中转配置：✅ 已有 (`~/.codex/config.toml` 多个 provider)
- `canvas-agent`：❌ 未 build + 未启动（要 `cd canvas-agent && npm install && npm run build && node dist/index.js`）

**两种"用"法：**
- **A. 画布右栏**：启动 canvas-agent → 画布右上角 Agent 填 `http://127.0.0.1:17371`+token → 在画布里跟 AI 对话操作画布。
- **B. 外部 CLI via MCP**：`codex mcp add infinite-canvas -- npx canvas-agent mcp` → 让 Codex 终端直接 get/put 画布（需 codex 已带 key 语境）。
