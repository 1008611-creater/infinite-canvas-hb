### 0.1 ★ 2026-09-13 线上实测：顺序风险已经变成现实（必读）

> **实测（匿名只读，未登录、未注册、未改数据）**：`POST /api/auth/register` 用合法邮箱 + 1 位密码 → **400 `password_too_short`**。
> 关闭注册时该接口应返回 **403 `registration_closed`**（`canvas-api/server.js` L109-129）。⇒ **线上注册开关是【开】的。**
> 该请求**没有创建任何账号**：源码顺序是先判 `ALLOW_REGISTER` → 校验邮箱 → 校验密码长度 → 才 `createUser()`。

**★ 由此暴露的真实敞口（B-6）**：`/api/` 刻意不吃 cookie 门禁（`nginx-docker.conf` L101-107 的原文注释），
而**注册成功会下发 `canvas_auth` 门禁 cookie**（`auth.js` `setSessionCookies()` → `setSitePassCookie()`，`LEGACY_COOKIE = "canvas_auth"`）。
⇒ **站点密码对「知道注册接口的人」是透明的。** 批次 1 上线后，陌生人可以：注册 → 拿到门禁 cookie → 调 `/ziyu/` → **花掉服务器上的紫域额度**。

**次生风险（未验证）**：`promoteToAdminIfFirst()` 的判据是 `count(*) <= 1` → `role='admin'`。
**若库里目前是 0 个用户，下一个注册者就会成为管理员**。本会话没有探测（唯一手段是真实注册 = 写数据），**必须由你在服务器侧查 `users` 表**。

**★ 因此批次 2 的正确顺序被改写为**（原顺序「先开注册、再撤门禁」有资金风险）：

```
1) 服务器 .env 加 CANVAS_ALLOW_REGISTER=0 → 重建 api 容器        ← 立刻做，最高优先
2) 查 users 表：确认你本人 role='admin'，且没有陌生人账号
3) 批次 1 落地：额度体系对所有 /ziyu/ 调用生效（requireAuth + 余额预扣）
4) 收紧 /api/auth/verify 的 legacy 分支（server.js L89-96 同时接受真会话或 legacy cookie）
5) 最后才放开公开注册 / 撤四处门禁
```

> **关键认知**：`/ziyu/` 的 cookie 门禁**不是资金防线**（可自助获得）。**唯一那道锁是额度体系** ——
> 这也是为什么批次 1 必须先于批次 2 上线，且上线后要先确认 `/ziyu/` 的每一条路由都挂了 `requireAuth`。
> 证据与复现命令：`docs/STATUS_20260913_LIVE_GATE.md`。

## 1. 验收项

### B2-1 · 首页不再被门禁拦住（对应落地器 B1）

**做什么**：用**无 cookie 的无痕窗口**打开 `https://hb.cauai.fun/`。

**期望**：HTTP 200，**能打开画布外壳**，地址栏**不再跳到 `/login.html`**。

**证据**：无痕窗口截图（含地址栏完整 URL）+ 时间戳。

**不过怎么办**：`location /` 块里的 `if ($canvas_authed = 0) { return 302 /login.html; }` 三行没删干净，
或删多了把 `try_files $uri $uri/ /index.html;` 一起删了（后者表现为 403/404 而不是跳登录页）。

> ★ 这里有个**容易误判**的点：批次 2 撤的是 cookie 门禁，**不是登录功能**。
> 撤掉之后前端仍应能正常调 `/agnes/auth` 登录 —— 见 B2-6 的反向断言。

### B2-2 · 静态资源与运行期配置不再被门禁拦住（对应落地器 B2 / B3）

**做什么**：无 cookie 无痕窗口直接访问：

1. 一个真实的 `https://hb.cauai.fun/assets/<某构建产物文件>`
2. `https://hb.cauai.fun/config.js`

**期望**：两者均 **HTTP 200**（`/config.js` 响应头带 `Cache-Control: no-store`）。

**证据**：两个 URL 的截图或响应头原文 + 时间戳。

**不过怎么办**：分别检查 `location /assets/` 与 `location = /config.js` 块里的三行 `if` 是否删净。
**注意不要删到 `expires 30d;` / `add_header Cache-Control ...`** —— 那两行是缓存策略，与门禁无关，删了会导致静态资源反复重下。

> ★ **本项就是 snippet 的 U1 点名要做的那一条**：
> `auth_request` + `error_page` + 具名 location 返回 JSON 的组合写法**从未在真实 nginx 上跑过**，
> 只有真机跑过 B2-2 / B2-4 之后，U1 才能从「未验证」改成「已验证」。

### B2-4 · ★ 免费试拍限次真的生效（对应落地器 B5）—— 本批次最关键的一项

> **这是批次 2 唯一的资金安全阀。撤门禁之后，`/agnes/v1/videos` 是整站唯一会用真钱调上游的端点。**
> 这一段（`location = /agnes/v1/videos` + `auth_request` + 两个具名 location）**从未在真实 nginx 上跑过**（snippet U1）。

**准备**：两个浏览器状态 ——（a）无 cookie 无痕窗口；（b）已注册并登录的普通账号。

**做什么与期望**（**四条按顺序全做**）：

| # | 做什么 | 期望 |
|---|---|---|
| 4.1 | 无 cookie `POST https://hb.cauai.fun/agnes/v1/videos` | **401**，正文 `{"error":"auth_required","hint":"请先登录后再使用免费试拍"}` |
| 4.2 | 已登录，**第 1、2、3 次**提交 | **放行**（正常转发到 agnes，返回 200 / 任务已创建） |
| 4.3 | 已登录，**第 4 次**提交 | **403**，正文 `{"error":"FREE_TRIAL_EXHAUSTED",...}` |
| 4.4 | 次数用尽后，`GET /agnes/v1/videos/<已存在的任务 id>` | **仍然 200** —— **轮询不受限次影响** |

**证据**：四次请求的**状态码 + 响应正文**（可脱敏，但状态码与 `error` 字段必须原文）+ 时间戳。
建议同时留一张「账号面板里免费试拍剩余次数」的截图，与 4.2 / 4.3 的计数对得上。

**不过怎么办**（按症状查）：

| 症状 | 大概率原因 |
|---|---|
| **已登录也 401** | `proxy_set_header Cookie $http_cookie` 没把 cookie 带到 api —— **snippet U2，未验证项** |
| 第 4 次仍然是 200 | 精确匹配 location 没抢在 `location /agnes/` 前面命中；或发布后容器内还是旧 `default.conf` |
| 401 / 403 返回的是 HTML 而不是 JSON | `error_page` 与具名 location 的相互作用问题 —— **snippet U3，未验证项** |
| 完全放行、没限次 | 片段根本没插进容器（见第 5 节「确认容器内文件真的换了」） |
| 提交失败也扣次 | **这是已知的、不可消除的代价**（snippet R2）：`auth_request` 只能先放行后转发，拿不到上游结果，**提交即扣次、不退** |

**额度口径**：默认每账号每月 3 次，读服务器 `api.env` 的 `FREE_TRIAL_MONTHLY_LIMIT`
（`routes-credits.js` L90-93，默认 3）。周期键是服务器本地月的 `YYYY-MM`（`credits.js` L343 `currentPeriod()`），
**不是自然月零点整，也未处理时区** —— 这是 snippet U4 的未验证项，验收时请如实记录服务器时区下的实际重置时刻。

> ★ **必须一并验证的反面**：额度是按**账号**算的，不是按 IP。同一账号换设备、换网络，额度**不重置**。
> 如果实测发现换 IP 就能重置，说明限次没有真正落到 `free_trial_usage` 表上，必须停下来查。

## 3. 发布链路与「确认容器内文件真的换了」

本批次**只改 nginx 配置 + 前端一个常量**：

- 不需要改 `publish.sh` 的打包列表；
- 不需要改 `Dockerfile.api` 的 COPY；
- **不涉及 `.env`**（所以不存在「改了 `.env` 没重建容器」的坑）。

但 `nginx-docker.conf` 是发布时被 sed 替换占位符后覆盖到容器的，**必须走一次完整发布才生效**。
**不要只在服务器上手改 `default.conf`** —— 下次发布会把它盖掉，而且没人会记得。

**确认容器内文件真的换了**（这一步不能省，否则会出现「发布日志全绿、线上跑旧版」）：

```bash
# 进 web 容器，确认 default.conf 里有免费试拍片段
docker compose -f /opt/infinite-canvas/docker-compose.yml --project-directory /opt/infinite-canvas \
  exec -T web grep -n "canvas_free_trial_check" /etc/nginx/conf.d/default.conf
```

**期望**：至少打出两行（`auth_request /_canvas_free_trial_check;` 与 `location = /_canvas_free_trial_check {`）。
**打不出任何东西 = 发布没生效**，此时 B2-1 ~ B2-4 全部不必测。

> ⚠️ 命令里的服务名 `web` 来自 `deploy/docker-compose.yml` 的**静态阅读**，容器名 `canvas-web`。
> **未在真实服务器执行过**。执行前先 `docker compose config --services` 核对。

> ⚠️ 如果同时改了 `api.env`（例如 `FREE_TRIAL_MONTHLY_LIMIT`），**必须重建 api 容器**：
> `up -d --force-recreate api`。否则会出现「改了还是旧的」，而且日志里看不出来。
