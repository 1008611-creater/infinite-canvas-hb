## 0. 一句话

**批次 3 的回滚几乎不需要「发版」，只需要「关开关」** —— 它改的几乎全是外部连接，不是线上代码。
但它有**两个前两批都没有的陷阱**：

1. ★ **顺序陷阱**：撤 20128 的防火墙规则**必须早于**把前端渠道 baseUrl 改回 20128。
   顺序反了，连本机都连不上，现场看起来会像「回滚把中转搞坏了」。
2. ★ **关隧道 ≠ 撤销访问**：`canvas-agent` 的 CORS 白名单是**累积持久化**的
   （`setCors()` 会把首个带正确 token 的 Origin 写进 `~/.infinite-canvas/canvas-agent.json` 并 `saveConfig()`）。
   关掉隧道之后白名单还在，**下次暴露时原样生效**。

## 2. 主回滚步骤

### 2.1 通用顺序：先关外部入口，再关内部服务

无论回滚哪一项，顺序都是：

1. **停隧道**（外部入口没了）；
2. **停守卫 / 停新服务**（本机端口空出来）；
3. **撤防火墙规则**（让 20128 恢复原样）；
4. **改回画布侧配置**（前端 baseUrl / 画布节点，最后动）。

**为什么是这个顺序**：前三步都是「减」，只有第 4 步是「改配置」。
先把对外面收干净，再改内部，任何一步出错都还停在「收」的方向上，
不会出现「对外还开着、内部已经断了」的中间态。

> ★ 第 3 步和第 4 步**不能交换**，原因见 §4.1。

### 2.2 回滚 B3-1 · `canvas-agent` 对外暴露

**步骤**：

1. **停掉 `canvas-agent` 的对外隧道**（新起的那条，**不是** `cloudflared-canvas`）。
   > ★ 千万别误停 `cloudflared-canvas` —— 那是 `hb.cauai.fun` 的**主站**隧道，停了等于站点下线。
2. **撤掉守卫反代规则**（如果选的是选项 (b)，就是那个新的 guard 进程 + 它对应的反代配置）。
3. ★ **清 CORS 白名单**：

   要改的文件（Windows）：

   ```
   C:/Users/<你的用户名>/.infinite-canvas/canvas-agent.json
   ```

   把 `origins` 数组**清空**（或删掉该字段），然后**重启 `canvas-agent` 让它重新读配置**。

   **为什么必须做**：`setCors()`（`canvas-agent/src/server/http.ts` L521-535）会把
   **首次带正确 token 的 Origin** 记进白名单并 `saveConfig()`。这份白名单是**持久**的。
   只关隧道 = 暂时进不来，但白名单留着，**下次暴露时那些 Origin 直接就是白名单成员**。

4. **确认 `canvas-agent` 本机仍可用**：本机带 `x-canvas-agent-token` 头访问
   `http://127.0.0.1:17371/health` 应当正常。

**期望**：从公网访问那个隧道域名**超时 / 502**；本机 `127.0.0.1:17371` 正常。

> ★ **不要顺手改 `canvas-agent` 的 token**。token 存在 `~/.infinite-canvas/canvas-agent.json`，
> 换了它，**本机所有已配置的画布客户端都要重新配**。只有当你**确信 token 已经泄露**时才换 ——
> 那属于安全事件处置，不是回滚。

### 2.3 回滚 B3-2 / B3-3 · LLM 中转与 20128 防火墙

**★ 严格按这个顺序**：

1. **停 20129 的对外隧道**（外部入口没了）。
2. **停 `omniroute-guard` 进程**（20129 空出来）。
3. **撤防火墙规则**：

   ```powershell
   netsh advfirewall firewall delete rule name="omniroute-20128-block-remote"
   ```

4. **本机自测 20128 恢复**：

   ```powershell
   curl http://127.0.0.1:20128/v1/models
   ```

5. **改回画布侧的前端渠道 baseUrl**：从 20129 改回 `http://127.0.0.1:20128`。
   在画布的「设置 → 渠道」里改；如果当初是改的源码树默认常量，则改回后重新发布。

**期望**：第 4 步本机通；改完第 5 步画布能正常出片。

> ★ **第 3 步必须早于第 5 步**：如果你先把 baseUrl 改回 20128、而防火墙规则还挂着，
> 那么**本机走 `127.0.0.1` 仍然是通的**（Windows 入站规则不过滤回环），
> 但**任何非回环路径都会被打死**。现场表现是「有的机器能连、有的机器不能」，非常难查。
> 反过来「先撤规则、再改 baseUrl」，中间态只是「20128 短暂对外敞开」——
> **这是可接受的，因为 20128 本来就是本机在跑的服务。**

### 2.4 回滚 B3-4 / B3-5 · 画布内容

**不需要做任何事**：天宫漫剧的节点链与事实分层标注都是**画布上的数据**，
不在代码里，回滚代码不会动它们。

**如果你确实想撤掉画布上的内容**：那是**数据删除**，不是回滚。
动手前先导出快照（`canvas_export_snapshot`），并且记住：
画布数据落在 `/opt/canvas-api-sync`（画布内云同步）与 `/opt/canvas-postgres`（账号与项目）
两个**不可再生**的数据卷里，**任何删除前必须单独确认**（`AGENTS.md` §5）。

### 2.5 回滚 B3-6 / B3-7 · 对账与告警

属批次 1 的面，**回滚见 `implementation/deploy/ROLLBACK.md` §4.1（R-01）**。

> ⚠️ 一条只读铁律：**对账先只读**。发现余额差异**不要直接改表** ——
> 走 `POST /api/admin/credits/adjust`（会写 `credit_adjustments` 留痕）。

## 3. 环境变量类回滚

### 3.1 本批次不涉及任何 `.env`

批次 3 **不新增环境变量**，`/opt/infinite-canvas/api/api.env` 零改动。
所以**不存在**「改了 `.env` 必须重建容器」这条坑。

> 唯一可能碰到「环境变量」的情况：你**自己**给 `omniroute-guard` 或新 guard 设了变量（如 `GUARD_TOKEN`）。
> 那些是**本机进程的环境变量**，不是画布源站的 `.env`；
> 改它们只需重启对应进程，**不需要碰 docker**。

### 3.2 ★ `AUTH_COOKIE` / `CANVAS_LEGACY_TOKEN` 在任何回滚里都不许动

- 它是「已登录」的凭证，**换一次 = 所有用户被迫重新登录**（`AGENTS.md` §2）。
- `CANVAS_LEGACY_TOKEN` 与它**同值**，必须同步保持。
- 批次 3 的所有回滚动作**都不需要**碰这两个值。如果你发现自己的回滚步骤里要改它，说明走错路了。

### 3.3 ★ `GUARD_TOKEN` 的处理

`tools/omniroute-guard/server.js` 的 `GUARD_TOKEN` **必填、无默认**（缺失直接 `exit(1)`）。
回滚时：

- **不要**把 `GUARD_TOKEN` 改成空值或弱口令 —— 那不是回滚，是把守卫拆了。
- 如果你只是**停用** 20129，**直接停进程**即可，环境变量留着无所谓。
- 只有当你**确信 `GUARD_TOKEN` 已泄露**时才换。启动日志会打印 token 前 4 / 后 4 位，**别外贴日志**。

## 4. 方向性风险（回滚特有）

### 4.1 ★ 顺序陷阱：撤防火墙规则必须早于改 baseUrl

见 §2.3 的说明块。**这是本手册最容易出错的一条。**
一句话记法：**先让 20128 重新可用，再把配置指回去。**

### 4.2 ★ 关隧道 ≠ 撤销访问

见 §2.2 第 3 步。CORS 白名单是**持久**的，清完还要**重启进程**才生效。

### 4.3 「事实分层」可能从「数据」变成「代码」

`batch3-ops.md` §5.2 已写明：四类标注（`source_fact` / `adaptation` / 影视化补强 / `unverified`）
**目前只规定了分类名称**，「用什么字段存、怎么在画布上渲染」尚未设计。

- 如果最终**不改前端代码**（例如只靠节点标题 / 备注约定）→ 属数据，回滚无需动作。
- 如果最终**要改前端代码**（加字段、加渲染）→ **批次 3 就不再是「不改源码树」的批次**，
  回滚要走「换软链回上一个 release」这条老路，并且要**先停下来回报**再决定。

### 4.4 quick tunnel 在回滚时也不许开

> ⚠️ **quick tunnel（`trycloudflare` 临时域名）必须保持关闭**（`docs/DECISIONS.md` D3、
> `ROLLBACK.md` L217-218）。
> 回滚过程中**不要**为了图快临时开一个 quick tunnel 来「先让服务通着」——
> 那是一个**无鉴权的公网入口**，等于把 20128 / `canvas-agent` 直接挂公网。
> 回滚期间的正确姿势是**服务就是不通的**，不是「先开个临时口子」。

### 4.5 回滚不会影响画布主站

批次 3 的所有改动都在**本机**与**独立隧道**上，与 `hb.cauai.fun` 的源站（机器 A）解耦。
**如果回滚过程中主站出问题，那大概率不是批次 3 造成的**，不要顺着这条线查。

## 5. 逐项回滚对照表（出事了先看这张表）

| 现象 | 大概率原因 | 回滚动作 | 参考 |
| --- | --- | --- | --- |
| 画布出片突然全挂、报连不上模型 | 20129 守卫进程停了 / 隧道断了，而 baseUrl 还指着 20129 | 按 §2.3 顺序回滚：**先撤防火墙规则**，再把 baseUrl 改回 20128 | §2.3 / §4.1 |
| 「本机 curl 通、别的机器不通」 | 防火墙规则还挂着，但配置已改回 20128 | 撤防火墙规则（`netsh ... delete rule`） | §2.3 |
| 公网还能访问 `canvas-agent` | 隧道没停干净 / 有第二条隧道 / 守卫反代规则没撤 | 逐条 `cloudflared tunnel list` 核对，撤掉多余入口 | §2.2 |
| 换了域名还能访问 agent | CORS 白名单是累积的，老 Origin 还在 | 清 `~/.infinite-canvas/canvas-agent.json` 的 `origins` 并重启 | §2.2 / §4.2 |
| 本机画布客户端突然要重新配 token | 顺手换了 `canvas-agent` 的 token | **不要为了回滚换 token**；已换则逐个客户端重配 | §2.2 |
| `omniroute-guard` 起不来、直接退出 | `GUARD_TOKEN` 没设或为空（必填无默认） | 设一个长随机串再起；**不要**改成弱口令 | §3.3 |
| 主站 `hb.cauai.fun` 打不开 | 误停了 `cloudflared-canvas` 主站隧道 | 重新启动主站隧道；与批次 3 无关 | §2.2 |
| 回滚后发现画布上的三集流程不见了 | 删了画布数据（回滚本身不会造成） | 从快照恢复；**数据卷不可再生，动手前单独确认** | §2.4 |
| 余额对不上 | 紫域 `cost` 与本地扣减不一致 | 走 `/api/admin/credits/reconcile`，**先只读** | §2.5 |
