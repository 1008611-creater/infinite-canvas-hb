## 1. 验收项

### B3-1 · `canvas-agent` 对外可达且有鉴权（对应主清单 A-19）★ 卡 `D-agent-auth`

> ★★ **本项在 `D-agent-auth` 裁决之前**不许开始验收 —— 没裁决就没有「期望」可对照。
> 三个选项与代价见 §4，**不代替你决策**。

**做什么**：按裁决结果，经**守卫反代 + 具名隧道**从另一台设备访问 `canvas-agent`。

**期望**（三选一，取决于裁决）：

| 裁决 | 期望 |
| --- | --- |
| (a) 沿用现有 token | 另一台设备带对 token 可达；**不带 token 返回 401 `invalid token`** |
| (b) 另发凭据 + 守卫反代 | 另一台设备只看到守卫端口；**不带守卫凭据返回 401/403**；17371 **不直接对外** |
| (c) 不对外暴露 | 本机可达、外部不可达 —— **此时 A-19 的目标缩水为「本机可用」，不许写成「对外能力已交付」** |

**证据**：另一台设备的截图（含地址栏）+ 状态码 + 时间戳；**不许贴任何 token 原文**。

**不过怎么办**：

| 症状 | 大概率原因 |
| --- | --- |
| 外部完全连不上 | 隧道没起 / hostname 没配 / 服务只绑了 127.0.0.1 而隧道指向错端口 |
| 不带 token 也能调通 | 全局 token 中间件（`src/server/http.ts` L125-128）没生效，或守卫没挡 |
| 带对 token 却 403 `origin not allowed` | CORS 白名单问题（`setCors()` L521-535），见下面 ★ |

> ★ **`validToken()`（`src/server/http.ts` L538-541）同时接受请求头与 `?token=` 查询参数。**
> 一旦对外暴露，走 `?token=` 的请求会把 token 写进浏览器历史、反向代理日志、Referer 头。
> 这是选项 (a) 的直接代价，不是理论风险。验收时请**如实记录你实际用的是哪种传法**。

> ★ **暴露前必须知道的五条危险路由**：`POST /agent/codex/turn`、`POST /agent/claude/turn`、
> `POST /agent/local-file/reveal`、`POST /api/tools`（34 个工具任意调用）、`POST /agent/codex/approval`。
> 五条合起来 = **把本机的执行能力交给对方**。鉴权强度必须按这个量级来设计。

> ★ **CORS 白名单是累积的**：`setCors()`（L521-535）会把**首次带正确 token 的 Origin** 永久记进
> `~/.infinite-canvas/canvas-agent.json`。**关掉隧道 ≠ 撤销访问** —— 回滚时记得一起清白名单（见回滚手册 §4）。

### B3-2 · LLM 中转跨设备可用（对应主清单 A-20）

**做什么**：在机器 B 上起 `tools/omniroute-guard`（默认 20129），从**另一台设备**发一个 LLM 请求。

**期望**：可达、能出词。

**证据**：另一台设备上的请求截图 + 返回正文首 200 字符（**不许贴 token**）+ 时间戳。

**不过怎么办**：

| 症状 | 大概率原因 |
| --- | --- |
| 进程起不来，打印一行错误就退出 | `GUARD_TOKEN` 没设 —— 它**无默认值，必填**（缺失即退出，这是故意的守卫） |
| 本机通、外部不通 | 隧道没起 / 没指向 20129 / 防火墙挡了 |
| 外部 401 | 请求没带对 token；比较逻辑在 `tokenMatches()`（`server.js` L42-50） |
| 浏览器里 CORS 报错 | `GUARD_ALLOW_ORIGIN` 默认 `*`，若被改成具体域名而前端来源不匹配就会挡 |

> ★ **启动日志会打印 token 的前 4 位与后 4 位** —— 不要把启动日志贴到任何公开处（群、issue、截图）。
> ★ **不要为了图快把 `GUARD_TOKEN` 留空或改成弱口令** —— 它挡在 20128 前面，是唯一那道门。
> ★ `tokenMatches()` 是**定长异或比较**（防时序侧信道），**不要改成 `===`**。

### B3-3 · 20128 收到本机 + quick tunnel 保持关闭（对应主清单 A-20 的两条风险确认）

> 这两条**不是新功能，是风险处置**。A-20 的「可达」由 B3-2 验收，本项验收「**可达的同时没有裸奔**」。

**做什么（两条都要做）**：

1. 在机器 B 上加防火墙规则，只允许本机访问 20128。
2. 确认 quick tunnel（`trycloudflare` 临时域名）**处于关闭状态**。

**期望**：

| # | 期望 |
| --- | --- |
| 3.1 | 本机 `curl http://127.0.0.1:20128/v1/models` **通** |
| 3.2 | 从**另一台设备** `curl http://<机器B的IP>:20128/v1/models` **超时/拒绝** |
| 3.3 | 对外只有 20129 可达，且**要 token** |
| 3.4 | `cloudflared tunnel list` / 进程列表里**没有** quick tunnel |

**证据**：防火墙规则原文（`netsh advfirewall firewall show rule name=...`）+ 两条 curl 的结果 + 隧道列表 + 时间戳。

**不过怎么办**：

| 症状 | 大概率原因 |
| --- | --- |
| 3.2 从外部仍能连上 | 规则没生效（名字写错 / 没加 `dir=in` / 加成了出站） |
| **本机也连不上了** | 规则把回环一起挡了（理论上不会：Windows 入站规则不过滤回环，但**未验证**）→ 先撤规则（见回滚手册 §4） |
| WSL 里连不上 20128 | **WSL2 走 NAT，会被这条规则一起挡** —— 有 WSL 访问需求就**不要加**这条规则（操作手册 §4.4） |
| 外部出现 `*.trycloudflare.com` 地址 | quick tunnel 被打开了 —— **立刻关掉**，那是无鉴权公网入口 |

> ★ **WSL 例外必须先想清楚**：加规则之前确认你有没有「从 WSL 访问 20128」的用法。
> ★ **quick tunnel 在任何时候都不许开**，包括回滚时图快（`ROLLBACK.md` L217-218）。

### B3-6 · 每日对账可用（对应主清单 A-23）

**做什么**：比对两侧数据：

| 侧 | 接口 |
| --- | --- |
| 本地 | `GET /api/admin/credits/reconcile?days=1`（批次 1 提供，`canvas-api/routes-credits.js` L384，需管理员） |
| 紫域 | `GET /api/v1/jobs?limit=50`（官方对账入口，limit 最大 100） |

**期望**：能看出「本地扣减」与「紫域 `cost`」的差异，且**有差异能定位到具体 task id**。

**证据**：两侧输出原文（可脱敏，但 task id / cost / 状态字段必须原文）+ 时间戳。

**不过怎么办**：

| 症状 | 大概率原因 |
| --- | --- |
| 本地接口 403 | 当前账号不是管理员（`requireAdmin`） |
| 两侧条数差很多 | 紫域只返回最近 N 条（`limit`）；先把 `limit` 拉到 100 再比 |
| 有差异但定位不到 task id | 本地流水里没记紫域 task id —— **这是要如实记录的设计缺口**，不要在本批次临时改表 |

> ⚠️ **2026-09-13 追加**：本项有一个**必须先排除的假绿**——`channel_usage` 表若为空，
> 对账接口会返回**空数组**，看起来像"账全对"。该表在 2026-09-13 之前**没有任何写入点**（全仓命中 0 处）。
> **先 `SELECT count(*) FROM channel_usage` 确认非空，再看差异列表。表为空 ⇒ 本项判 FAIL。**
> 详见 `docs/VERIFICATION_20260913_BILLING.md` §七之三（缺陷 B）。

> ★ **一律先只读**。不要为了「把账修平」直接改表 —— 对账是**发现**差异，不是抹平差异。
> 需要修的时候走 `POST /api/admin/credits/adjust`（会写 `credit_adjustments` 留痕）。
> ★ **失败任务不保证退积分**，一律以紫域返回的 `cost` 字段对账（实测失败任务有记 200 积分的也有记 0 的）。

## 4. ★ 专项：`D-agent-auth` 硬阻塞（B3-1 的唯一前置）

**为什么单列**：这是批次 3 **唯一一个「不裁决就没法验收」**的项。其余六项可以先做。

**问题**：`canvas-agent` 对外暴露时，鉴权用什么形态？

**三个选项**（完整代价表在 `batch3-ops.md` §4.2，这里给结论摘要）：

| 选项 | 做法 | 主要代价 |
| --- | --- | --- |
| **(a) 沿用现有 token** | 直接把 17371 经隧道暴露 | 改动最小；但 `?token=` 会进日志 / 历史，**token 泄露 = 整机 agent 可被驱动** |
| **(b) 另发凭据 + 守卫反代** | 照 `omniroute-guard` 模式新增 `canvas-agent-guard`：只绑本机、独立凭据、具名隧道 | 多一层进程；公开面只剩一个受控端口，且**不暴露 `?token=` 这条路径** |
